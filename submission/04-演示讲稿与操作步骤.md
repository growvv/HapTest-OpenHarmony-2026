6. **6:40–8:00，工程与后续。** 介绍接口、异常处理、许可证、独立作者职责及真机验收计划。回答版本兼容、模型可靠性、帧类型筛选等问题。

## 无设备也能展示的步骤

在仓库根目录执行：

```powershell
npm run build
npm test -- --run
node bin/haptest perf analyze --db submission/05-辅助材料/样本/frames-fixture.db --output out/demo-frames --ipid 10 --type app --refresh-rate 60 --jank-flags 7
```

打开 `out/demo-frames/frames.html`。说明这是人工样本：有效应用帧 6 个、超预算 2 个、P95=34 ms。查看 JSON 中的 invalidFrameCount 与原始 flag，展示筛选及证据保存能力。展示 `test/unit/multimodal_planner.test.ts` 的本地 HTTP 协议验证，避免把模拟响应讲成在线模型演示。

## 真机演示步骤

按 [功能使用文档](../doc/multimodal-and-frames.md) 配置 HDC、模型服务与 trace_streamer。先运行 doctor 并检查当前截图，再对测试应用进行规划预览，确认候选后运行 --execute。演示一次 5 秒 trace 采集及离线帧解析。

录屏画面建议包含终端、设备屏幕与帧报告。密钥只在本机环境变量中设置，不出现在录屏中。出现 STALE_OBSERVATION 或不确定动作时，说明停止与重新观察机制，不反复盲点。

## 常见答辩问题

- **系统级创新在哪里？** 主机框架将系统测试服务、页面迁移模型、观察约束和系统 trace 接在一起，贡献在框架与工具链层。
- **多模态是否只是文本提示？** 新请求的内容数组同时包含截图 base64 和候选 JSON，测试通过本地 HTTP 服务检查实际传输；在线模型效果需要真机任务集验证。
- **是否真的发现系统卡顿？** 已能逐帧读取与报告耗时。系统卡顿 flag 需版本校准，样本只证明计算与导出逻辑。
- **独立作者与开源来源如何区分？** 本次参赛由刘发荣独立负责，保留既有开源代码和依赖的版权归属，不将团队研究统计改署为个人新增结果。
